本篇是「摄影师项目管理工作台」的完整搭建 SOP。一句话：把「这单拍到哪一步、客户要什么、片子存在哪」从一堆微信对话框里，挪到一个打开就能看的单子上。
一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：一天拍两场，晚上回家想不起 A 客户到底要暖调还是冷调，翻微信翻了 20 分钟，还翻错了人。
瞬间二：交完片三天后客户说「上次说的那三张不要了」，你完全想不起是哪三张，只能全部重出。
瞬间三：硬盘里 4T 素材，找某次拍摄的原片全靠回忆文件夹名。有时候找一个片子比拍它还久。
摄影师的钱是靠「档期」和「交付」赚的，但这两件事最容易被忘。这个工作台不管修图，只管把每一单从谈到交付的过程钉住。

为什么是"桌面软件"而不是表格？拍摄现场你是导演，拍完你就变成客服。这两个角色切换最怕的是信息断档——客户要的暖调、必拍的三个镜头、上次说不要的那几张，全在脑子里。软件的作用是让这些在拍摄前和交付前都能看见，而不是等你翻微信。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\摄影项目。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备几条真实数据（纸面想好就行，不用打字）：本月已排的 2-3 场拍摄（日期、客户、类型）；最近一单客户的具体要求；你的交付渠道（网盘还是微信）。

唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。
三、第一步：跟 WorkBuddy 把话说清楚（提示词一）
3.1 开工操作
打开 WorkBuddy，点新建任务，模式选 Agent 模式（它能自己动手建文件，别选纯问答模式）。
把工作目录设成第二章建好的那个文件夹（比如 D:\我的工作台\摄影项目）。设错也不致命，就是文件会落别处，你得多翻一下。
在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"摄影师项目管理工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我做摄影（人像/婚礼/商业/写真）。痛点是：客户要求记不住、档期容易撞、交完片客户说要改但我忘了改哪几张、素材找不到。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个摄影师项目管理工作台"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"主要拍什么类型？"——人像/婚礼/商业/写真，选实际在接的
"订单状态分几步？"——谈单/已定档/已拍/待修/已交付/已收款
"需求要记多细？"——风格、色调、必拍清单、明确的不要
"交付走什么渠道？"——网盘/微信/线下，记一下方便查
"要不要管器材？"——第一版不要，后面再说
这里出现第一个"需要你输入"的点：上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）
4.1 提示词二：要一份方案
需求确认完，先别放它写代码。继续粘贴：

需求确认了。现在还是不要写代码。请先给我一份搭建方案，包含四部分：
1. 页面结构：这个软件一共几个页面，每个页面放什么内容；
2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一条记录"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。
方案用中文写，控制在 500 字以内，不要贴代码。
4.2 方案怎么验收：只看三样
500 字方案一分钟看完，重点盯三处：

看什么

合格标准

订单必须有「拍摄日期」和「交付日期」

两个日期是整个工作台的骨架，缺一个档期就排不了

需求卡必须有「必拍清单」

客户最容易在交付时说「这个怎么没拍到」，就是这个原因

有交付状态

不知道哪单还没交，就会有单子烂在硬盘里
4.3 方案不满意怎么改（提示词三，通用句式）

方案整体可以，改三处：
1. 档期页按月历显示，有拍摄的日子标色；
2. 订单按交付日排序，逾期的置顶标红；
3. 把修图、选片相关功能全砍掉。
确认后给我更新版方案，还是不要代码。

一次最多改三处。这不是规矩是经验：改的条数越多，每一处改得越潦草，而且你回头都验不了。
五、第三步：生成第一版（提示词四，这次真写代码）
5.1 提示词四：带四条硬约束
方案点头之后，粘贴这段。四条硬约束一条都别删——每一条背后都是踩过的坑：

方案确认，开始做第一版。四条硬要求，必须全部满足：
1. 只做成一个单独的 HTML 文件，所有代码都写在这一个文件里，不要拆多个文件，不要安装任何依赖，做完我双击这个文件就能用；
2. 数据全部存在我电脑本地，刷新页面、关掉浏览器再打开，数据都不能丢；
3. 界面全中文，做得干净、字大、好点，我每天要打开好几次，别做成演示 demo 的样子；
4. 需求卡要能贴参考图（客户发来的示意图，我要能直接存下来看）
做完以后，你自己把整个软件从头到尾完整点一遍，告诉我哪里顺手、哪里会让我困惑。
做完告诉我：文件叫什么名字、放在哪个文件夹。

约束

5.3 第一版验收清单（5 分钟点完）
WorkBuddy 做完后，去工作目录找到那个 HTML 文件，双击打开，然后逐条打勾：
建 2 个订单，填客户、拍摄日期、交付日期

需求卡能贴一张参考图
关掉重开数据不丢

第一版只验"通不通"，不验"好不好看"。丑、慢、布局怪，都留到第七章的迭代环节统一处理。第一版就追求完美，你会陷入无止境的细节，搭不完。
六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
录进去：本月真实的 2-3 场拍摄、最近一单客户的原话要求（照抄，别总结）、你一单的平均报价和平均修图天数。最后这个数字，是你判断接不接下一单的依据。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它要求填「拍摄时长」，可你按半天一天算；比如它把「器材」设成必填，你不想记。
第二类：流程不顺手。比如看需求卡要点订单、点详情、切到需求页，三步；拍摄前你想一键就看到。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开档期页，看到的是你本月真实的拍摄安排，哪天有活一眼清楚。

7.1 迭代的三条纪律
一次只提 1~3 条。一次丢十条过去，它改出来的东西你自己都验不过来，坏一处你还不知道是哪条改坏的。
改完用一遍，再提下一轮。改动生效后至少真实使用半天，硌手的地方会自己冒出来。
提示词里带现象，别带结论。说"我点保存没反应"比说"保存功能坏了，你修一下"效果好——前者是证据，后者是让你俩一起猜。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 摄影工作台备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每次用完固定导出一次，存进 D:\我的工作台\备份。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：
11.1 需求整理成人话清单
客户的原话永远是散的，得有人帮你归拢。

这是我客户发来的原话（粘贴）：……。请帮我整理成一份拍摄需求清单：
1. 明确的风格和色调要求；
2. 必拍清单；
3. 客户明确说不要的；
4. 还没说清楚、我需要再问的问题（最多三个）。
11.2 交付话术
交付那一刻，专业度决定客户下次还找不找你。

我这单拍的是【类型】，客户要求是【……】，现在片子修完了要发给客户。请帮我写一段交付消息：说明交了什么、多少张、修了哪些、后续修改规则（比如免费改 3 张），语气专业但别端着。
11.3 定价参考
摄影最容易犯的错，是按「拍了几个小时」报价。

我做【类型】摄影，一单【X】小时，出【Y】张，目前报价【Z】。请帮我分析这个报价合不合理，参考同类市场，给出三个调整方案（涨价/加套餐/减少出片量），并说明各自风险。
