本篇是「咖啡冲煮实验工作台」的完整搭建 SOP。一句话：把「这包豆子怎么冲最好喝」从每次瞎试，变成一张有记录的实验表——三个月后你会有自己的配方本。
一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：买了一包好豆子，冲出来很好喝，第二次再冲就淡了。粉水比、水温、研磨度全凭手感，永远复现不了。
瞬间二：看博主说 92 度、1 比 15、2 分 30 秒，照做了，结果酸得喝不下——因为你的磨豆机、你的豆子跟他不一样。
瞬间三：喝过最好喝的一杯是在某个咖啡馆。想复现，但完全不知道人家怎么冲的，只记得「很甜」。
咖啡是典型的变量游戏：粉量、水量、研磨度、水温、时间，五个变量变一个，味道就变。人脑记不住五维组合，但一张表可以。

为什么是"桌面软件"而不是表格？咖啡圈有句话：所有的玄学都是变量没控住。你觉得今天这杯更好喝，可能只是水温高了 2 度。软件的作用是把五个变量钉住，让你知道「好喝」是怎么来的，也就能复制。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\咖啡冲煮。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备几条真实数据（纸面想好就行，不用打字）：你现在这包豆子的信息（产地、烘焙度、烘焙日期）；你常用的冲煮参数（粉量、水量、水温）；最近一次觉得好喝的冲煮，你还记得什么。

唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。
三、第一步：跟 WorkBuddy 把话说清楚（提示词一）
3.1 开工操作
打开 WorkBuddy，点新建任务，模式选 Agent 模式（它能自己动手建文件，别选纯问答模式）。
把工作目录设成第二章建好的那个文件夹（比如 D:\我的工作台\咖啡冲煮）。设错也不致命，就是文件会落别处，你得多翻一下。
在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"咖啡冲煮实验工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我在家手冲咖啡。痛点是：好喝的冲不出来第二次、参数全凭手感、看别人的配方照做不好喝、喝过的风味记不住。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个咖啡冲煮实验工作台"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"用什么冲？"——手冲/V60/爱乐压/意式，选实际的
"要记哪些参数？"——粉量、水量、研磨度、水温、总时间
"评分怎么打？"——1-5 星加三个风味词就够
"要不要管豆子库存？"——要，豆子会过期
"要不要存配方？"——要，这是核心
这里出现第一个"需要你输入"的点：上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）
4.1 提示词二：要一份方案
需求确认完，先别放它写代码。继续粘贴：

需求确认了。现在还是不要写代码。请先给我一份搭建方案，包含四部分：
1. 页面结构：这个软件一共几个页面，每个页面放什么内容；
2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一条记录"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。
方案用中文写，控制在 500 字以内，不要贴代码。
4.2 方案怎么验收：只看三样
500 字方案一分钟看完，重点盯三处：

合格标准

少一个，这次记录就无法复现

4.3 方案不满意怎么改（提示词三，通用句式）

方案整体可以，改三处：
1. 冲煮记录按豆子分组，同一支豆子的记录放一起；
2. 评分用星级，一眼能看出最好的是哪次；
3. 把购买、比价、百科全砍掉。

一次最多改三处。这不是规矩是经验：改的条数越多，每一处改得越潦草，而且你回头都验不了。

六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
录进去：你现在这包豆子的真实信息、你最近三次冲煮的参数（记不清就写你现在习惯用的）、最近一次觉得好喝是什么味道。用你自己的话，别用「明亮的酸」这种词，就写「像橘子皮」。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它要求研磨度填「微米」，但你的磨豆机只有刻度 1-10；比如它把「TDS 浓度」设成字段，你没有测量仪。
第二类：流程不顺手。比如记一次冲煮要填八个字段，太累；比如想对比两次记录，要来回翻页。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开冲煮记录，能看到你自己真实的三次冲煮，参数和评分都在。

7.1 迭代的三条纪律
一次只提 1~3 条。一次丢十条过去，它改出来的东西你自己都验不过来，坏一处你还不知道是哪条改坏的。
改完用一遍，再提下一轮。改动生效后至少真实使用半天，硌手的地方会自己冒出来。
提示词里带现象，别带结论。说"我点保存没反应"比说"保存功能坏了，你修一下"效果好——前者是证据，后者是让你俩一起猜。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 咖啡工作台备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每次用完固定导出一次，存进 D:\我的工作台\备份。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：
11.1 参数调整建议
咖啡调参有明确的方向性，不用瞎试。

我在冲【豆子：产地、烘焙度、烘焙后第 X 天】，目前参数是【粉 X 克、水 X 克、研磨 X、水温 X 度、总时间 X 分 X 秒】，喝起来【太酸/太苦/太淡/发涩】。请告诉我该调哪个变量、往哪个方向调、一次调多少，并说明为什么。
11.2 风味翻译
你尝到的味道，需要翻译成能调整的参数。

这杯咖啡我喝到的感觉是【像橘子皮、后面有点红茶味、凉了之后发甜】。请帮我翻译成咖啡圈的描述词，并告诉我这大概说明豆子的什么特点、下次冲的时候可以怎么调整来放大这个味道。
11.3 豆子推荐参考
