# WorkBuddy 操作图文指南

01_WorkBuddy 操作图文指南
WorkBuddy 保姆级图文上手手册
从安装、第一项任务到文件/PDF/表格与排错
2026年7月整理版 · 操作前请核对当前官方界面

1. 先理解：WorkBuddy 适合做什么
WorkBuddy 是面向职场任务的桌面 AI 智能体工作台。与普通聊天式 AI 相比，重点不是“多聊几句”，而是围绕目标规划步骤、调用资料并交付可检查的结果。
适合：整理文件、总结资料、分析表格、生成报告、处理重复性办公任务。
不适合：未经确认直接删除文件、自动外发重要内容、替代专业法律/医疗/财务判断。
最佳用法：把任务写成“目标 + 输入 + 输出 + 边界 + 验收标准”。

新手原则
第一天先用复制件和测试文件夹；任何涉及覆盖、删除、批量移动或外发的任务，都先要求“只预览，不执行”。

2. 安装与首次进入

操作路径图：安装与首次使用
打开官方 WorkBuddy 产品页，确认当前系统要求与下载入口。
选择 Windows 或 macOS 对应安装包。
安装完成后登录；若遇到登录异常，先确认网络、账号和客户端版本。
第一次不要直接处理真实工作目录，先建立一个“WorkBuddy测试”文件夹。
输入一个无风险测试任务，确认基础对话和任务执行正常。
建议测试指令：

可直接复制
请先不要修改任何文件。请告诉我你当前能协助完成哪些任务，并按“文件处理、文档、表格、学习、内容创作”五类各举3个例子。

3. 第一个可靠任务怎么写

操作路径图：把一句模糊需求写成可验收任务
模糊指令“帮我整理文件”风险很高。更稳妥的写法是：

完整模板
目标：整理当前测试文件夹。输入：只读取该文件夹，不访问其他目录。输出：先生成分类预览表，列出原文件名、建议分类、目标文件夹。边界：不要移动、删除或覆盖任何文件。验收：我确认后再执行。

4. 文件处理：先预览再执行
复制一批测试文件到独立文件夹。
要求 WorkBuddy 先扫描并输出预览清单。
检查分类规则是否合理。
确认后只执行移动，不删除。
执行完要求生成变更日志。

可直接复制
请读取当前测试文件夹，按“文档、表格、图片、压缩包、其他”建议分类。先输出预览表，不移动任何文件。表格需包含：原文件名、扩展名、建议分类、目标文件夹、风险提示。

5. PDF：从“总结一下”升级为结构化提取
长 PDF 最常见的问题是摘要过泛。应先告诉它你读这份资料是为了做什么。

可直接复制
请阅读附件PDF。先用150字说明主旨，再输出：1) 5条关键结论；2) 文中明确出现的数据与出处页码；3) 仍需核实的内容；4) 面向普通人的行动清单。不要补充PDF未提供的事实。

6. 表格分析：先做数据体检

可直接复制
请先检查附件表格的数据质量，不要直接下业务结论。输出：字段说明、空值、重复值、明显异常值、日期格式问题、可能影响分析的风险。确认数据质量后，再分析趋势。

7. 周报与会议纪要
周报和会议纪要最适合普通用户：输入通常已经存在，只是零散。

周报模板
把下面零碎记录整理成周报，按“本周完成、关键成果、问题风险、下周计划”输出。不得虚构数据；没有数字就用事实描述。

会议纪要模板
请把会议记录整理为：背景、已确认决定、待确认问题、行动项。行动项必须包含负责人、截止时间；原文没有就标“待确认”，不要猜。

8. Skills、自动化与进阶功能
Skills、连接器、自动化等能力更新较快。使用前应先查看当前官方文档和客户端内可用入口，不要把第三方教程中的旧路径当成固定事实。
先确认功能是否在当前账号/版本开放。
先做单次任务，再考虑定时自动化。
自动化任务必须有失败处理和人工检查节点。
涉及外部账号授权时，只授予完成任务所需的最小权限。
9. 常见问题与排错

排错路径图
先检查账号是否登录、授权是否有效。
确认输入文件是否可访问，路径是否正确。
把大任务缩小为一个最小测试任务。
只修改一个变量后重试。
本地排错时可继续阅读 [常见问题与排错](027.md) 和 [版本说明](028.md)。

附录A：10个新手高频任务的详细写法
1. 下载文件夹整理
先复制一小批文件到测试目录。要求“只预览，不移动”，让工具生成原文件名、建议分类、目标目录、风险提示四列清单。确认后再执行，并要求保留变更日志。
2. 批量重命名照片
先要求根据拍摄日期、主题、序号生成“旧文件名→新文件名”对照表。遇到无法识别的照片统一标记“待人工命名”，不要强行猜测。
3. 长PDF总结
明确阅读目的，例如“我要做汇报”或“我要复习”。要求关键结论附页码；资料未提供的事实不得补充。
4. 两份文档对比
要求按新增、删除、修改、待确认四类输出。对于措辞变化但含义不变的内容，单独标记，避免制造虚假差异。
5. Excel销售分析
先检查空值、重复、日期格式和异常值，再分析趋势；避免把数据质量问题误判成业务结论。
6. 周报生成
输入一周零碎记录；禁止补写不存在的成果数字；按“完成、成果、风险、下周”输出。
7. 会议纪要
负责人和截止时间原文没有时必须写“待确认”。不要因为常识而自动补负责人。
8. 聊天记录提待办
先去掉闲聊，只保留明确承诺、请求、截止时间和待确认事项；引用原句作为证据。
9. 小红书笔记
先指定读者和真实经历边界，再生成标题、正文、分页；不要让AI编造“亲测”“爆了”等经历。
10. 项目交接
按项目状态、关键文件、联系人、风险、下一步输出；涉及账号密码时不要写入普通文档。

附录B：高质量任务说明书模板
模板字段
目标：最终要得到什么。
输入：允许读取哪些文件、文件夹或知识库。
处理：需要提取、分析、比较还是生成。
输出：文档、表格、清单、PPT大纲等。
边界：不得删除、不得外发、不得猜测。
验收：什么标准算完成。
完整示例
目标：整理当前测试文件夹。输入：只读取该目录。处理：按文件类型和项目主题建议分类。输出：预览表。边界：不移动、不删除、不覆盖。验收：每个文件必须有建议分类；无法判断的标“待确认”。

附录C：文件安全与隐私检查清单
操作前
使用复制件测试。
删除身份证号、账号密码、商业机密等不必要敏感信息。
确认目标目录，不把整个硬盘授权给单个任务。
操作中
先预览再执行。
批量任务分小批次。
要求生成变更日志。
操作后
检查文件数是否一致。
随机抽查结果。
保留原件直到确认完成。

附录D：遇到失败时的最小化测试法
原则
把“处理100个文件”缩小成“处理2个测试文件”。
把“生成完整报告”缩小成“只提取3个关键字段”。
把“自动化每天运行”缩小成“手动单次运行”。
记录方式
记录输入、指令、版本、错误现象和尝试过的修改。一次只改一个变量。
