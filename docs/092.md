WorkBuddy 工作台全套资料 · 第 06 篇
本篇是「自媒体博主创作工作台」的完整搭建 SOP。一句话：把「今天发什么」从每天早上抓头发，变成打开就有 20 个选题等着挑；把「发完就忘」的数据，变成下次选题的依据。
一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：坐在电脑前两小时，标题改了八遍，最后发出去播放 300。不知道是选题不行还是封面不行，只知道很挫败。
瞬间二：想到一个好选题，当时觉得绝了，转头记在备忘录里。两周后翻出来，已经完全想不起当时要说什么。
瞬间三：发了 60 条，数据好的那几条有什么共同点，说不清。每次都是「这条好像爆了」「这条不知道为什么没人看」，全靠玄学。
这个工作台干三件事：接住选题、管住进度、回流数据。它不帮你写稿（那是 WorkBuddy 的活），它负责让你每一次创作都不是从零开始。
1.2 成品长什么样：一个桌面上的小软件
先说清楚最终形态，免得你搭到一半发现跟想的不一样：
它会是你电脑桌面上的一个图标，双击就打开一个独立窗口，长得像个软件。不用联网也能用，所有数据都存在你自己电脑里，不需要注册任何账号，不需要装任何其他东西。

为什么是"桌面软件"而不是表格？创作者最大的浪费不是发得少，是同一个好选题想到三次、丢了三次。软件的第一价值是接住你的灵感，第二价值是让数据说话。这两件事手机备忘录都做不到，因为它不会在你打开的时候，把该做的事摆到眼前。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\自媒体创作。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备几条真实数据（纸面想好就行，不用打字）：你最近发过的 5 条内容（标题加大概数据）；现在想到但还没做的 3 个选题；你主要在哪些平台发。

唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。
三、第一步：跟 WorkBuddy 把话说清楚（提示词一）
3.1 开工操作
打开 WorkBuddy，点新建任务，模式选 Agent 模式（它能自己动手建文件，别选纯问答模式）。
把工作目录设成第二章建好的那个文件夹（比如 D:\我的工作台\自媒体创作）。设错也不致命，就是文件会落别处，你得多翻一下。
在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"自媒体博主创作工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我在做自媒体（公众号/视频号/小红书/B站）。痛点是：经常不知道发什么、好选题想到就忘、发完不看数据、不知道哪类内容该多做。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个自媒体博主创作工作台"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"主要发哪些平台？"——列平台名，一个平台一个标签
"内容形式有几种？"——图文/短视频/长视频，选实际在做的
"数据要记哪些？"——播放、点赞、评论、涨粉，四个够
"选题从哪来？"——自己想的、评论区、热点，三个来源
"要不要管草稿？"——不要，草稿在别处写，这里只记状态
这里出现第一个"需要你输入"的点：上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）
4.1 提示词二：要一份方案
需求确认完，先别放它写代码。继续粘贴：

需求确认了。现在还是不要写代码。请先给我一份搭建方案，包含四部分：
1. 页面结构：这个软件一共几个页面，每个页面放什么内容；
2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一条记录"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。
方案用中文写，控制在 500 字以内，不要贴代码。
4.2 方案怎么验收：只看三样
500 字方案一分钟看完，重点盯三处：

看什么

合格标准

选题必须有「来源」和「状态」

不知道来源就没法判断哪类灵感最靠谱；没状态就分不清该做什么

发布记录必须有「数据」字段

没数据的发布记录只是日记

有对比视图

4.3 方案不满意怎么改（提示词三，通用句式）

方案整体可以，改三处：
1. 选题池按状态加创建时间分组，待写的排最前；
2. 发布记录加数据录入快捷入口，发完 24 小时提醒补；
3. 把自动发布相关的东西全砍掉。
确认后给我更新版方案，还是不要代码。

一次最多改三处。这不是规矩是经验：改的条数越多，每一处改得越潦草，而且你回头都验不了。
五、第三步：生成第一版（提示词四，这次真写代码）
5.1 提示词四：带四条硬约束

WorkBuddy 做完后，去工作目录找到那个 HTML 文件，双击打开，然后逐条打勾：

第一版只验"通不通"，不验"好不好看"。丑、慢、布局怪，都留到第七章的迭代环节统一处理。第一版就追求完美，你会陷入无止境的细节，搭不完。
六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
录进去：最近 5 条真实内容（标题加你记得的数据，记不清就写大概）、现在想到的 3 个选题原话（别润色，就写你当时怎么想的）、你主要在发的 2-3 个平台。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它要求每条内容填「内容类型」，可你做的内容跨界，不知道该选哪个；比如它把「涨粉数」设成必填，可你那个平台看不到。
第二类：流程不顺手。比如录一条选题要点「新建」→填标题→选平台→选类型→保存；你想的是在输入框敲一句话回车。比如发布记录和数据是两页，你得来回跳。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开选题池，里面躺着你真实想到过的那三个选题，一句话一句，你能看懂当时想说什么。

7.1 迭代的三条纪律
一次只提 1~3 条。一次丢十条过去，它改出来的东西你自己都验不过来，坏一处你还不知道是哪条改坏的。
改完用一遍，再提下一轮。改动生效后至少真实使用半天，硌手的地方会自己冒出来。
提示词里带现象，别带结论。说"我点保存没反应"比说"保存功能坏了，你修一下"效果好——前者是证据，后者是让你俩一起猜。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 创作工作台备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每次用完固定导出一次，存进 D:\我的工作台\备份。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：
11.1 选题池扩列
一个人想选题会越想越窄，让它沿着你数据最好的方向扩。

这是我选题池里现有的 20 个选题（粘贴）。请帮我：
1. 按主题归类，看哪类最多、哪类空缺；
2. 沿着我数据最好的那类，再给我 10 个具体选题，要具体到能直接写的程度，不要「XX 的三个方法」这种空话。
11.2 爆款拆解
爆过的内容，值得拆一百遍。

这是我数据最好的一条内容（标题、封面描述、正文或脚本粘贴）。请拆解它为什么行：钩子在哪、节奏怎么走、哪句话最可能让人点赞。拆完给我三条可复用的结构模板。
11.3 数据诊断
