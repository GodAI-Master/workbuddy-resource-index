# 第四部分：技能插件与专家中心（第10-11章）

> [!NOTE]
> 📌
> <p><strong>这一册包含第 10-11 章，共 9 节。</strong>核心思路只有一个：<strong>别什么都自己搭</strong>。别人已经封装好的技能、已经调好的专家，直接借过来用——这是普通人跟高手差距最小的一步。</p>

## 第 10 章 Skill 精选与插件使用

<p><strong>先分清三个概念（很多人在这里绕晕）：</strong></p>

<table><thead><tr><th><p>概念</p></th><th><p>是什么</p></th><th><p>类比</p></th></tr></thead><tbody><tr><td><p><strong>技能（Skill）</strong></p></td><td><p>一套封装好的能力：包含指令、步骤、脚本</p></td><td><p>给员工的一套作业手册</p></td></tr><tr><td><p><strong>插件 / 连接器</strong></p></td><td><p>打通外部服务的接口：飞书、微信、数据库、浏览器</p></td><td><p>给员工开的门禁权限</p></td></tr><tr><td><p><strong>专家</strong></p></td><td><p>一个角色的完整设定：口吻、方法论、判断标准</p></td><td><p>请来的某个行业顾问</p></td></tr></tbody></table>

<p>一句话记：<strong>技能是&quot;会做什么&quot;，连接器是&quot;能碰到什么&quot;，专家是&quot;以谁的身份做&quot;。</strong></p>

### 10-1 技能安装，与 Agent Browser 插件

<p><strong>技能怎么装（三条路）：</strong></p>

<p>①<strong>技能市场搜</strong>：左侧「专家·技能·连接器」→ 切到技能 → 搜索关键词（比如&quot;PPT&quot;）→ 卡片右上角加号安装 → 装完在输入框打斜杠就能调出来。</p>

<p>②<strong>别人分享的技能包</strong>：拿到目录（通常是一个含 SKILL.md 的文件夹）→ 放进技能目录 → 重启或刷新后可见。</p>

<p>③<strong>自己写</strong>：把稳定跑过三次以上的指令整理成技能文档，见 10-7 后面的&quot;自己封装&quot;部分。</p>

<p><strong>Agent Browser 插件（这个最值得先装）：</strong></p>

<p>它的作用是让 AI 能<strong>真的打开浏览器去操作网页</strong>——填表单、点按钮、翻页、截图、抓取需要登录才能看的内容。普通搜索只能拿到网页文字，它能像人一样在页面上操作。</p>

<p><strong>典型用法：</strong></p>

<table><thead><tr><th><p>场景</p></th><th><p>指令</p></th></tr></thead><tbody><tr><td><p>批量查后台数据</p></td><td><p>&quot;打开 [后台地址]，登录后进入订单页，导出上月的订单明细到本地&quot;</p></td></tr><tr><td><p>抓竞品页面</p></td><td><p>&quot;打开 [竞品价格页]，把当前所有套餐名称和价格抓成表格，截图留证&quot;</p></td></tr><tr><td><p>重复性网页操作</p></td><td><p>&quot;在这个系统里把 [这批单号] 逐个查询状态，结果填回表格&quot;</p></td></tr><tr><td><p>验证自己的网页</p></td><td><p>&quot;打开我本地这个页面，检查在手机尺寸下排版有没有错位，截图给我&quot;</p></td></tr></tbody></table>

<p><strong>两个注意：</strong>① 涉及账号登录的，第一次要你手动登录一次，之后它复用会话；别把密码写进指令；② 网页结构改版后原来的操作会失效，重要的自动化流程要定期验证。</p>

### 10-2 技能精选：办公 Office 文档套件

<p><strong>解决什么：</strong>让 AI 真正能生成和编辑 docx / xlsx / pptx，而不是给你一段文字让你自己粘贴。</p>

<p><strong>三个能力层级（看你在哪一层）：</strong></p>

<p>①<strong>生成</strong>：从零做一份 Word/Excel/PPT，含标题层级、表格、图表、页码。</p>

<p>②<strong>编辑</strong>：在已有文件上改——改格式、加章节、替换数据、调排版，原文件结构不乱。</p>

<p>③<strong>批量</strong>：一次处理几十个文件（批量套模板、批量导出 PDF、批量替换内容）。</p>

<p><strong>典型用法：</strong></p>

<p>· &quot;把这份 markdown 转成正式 Word 报告，加目录、页眉页脚、图表编号&quot;<br/>· &quot;在这个 Excel 里加一列&#39;同比&#39;，公式算好，格式跟旁边的列保持一致&quot;<br/>· &quot;按这个模板批量生成 30 份通知书，名字从名单表里取&quot;· &quot;把这份 PPT 的配色统一成公司蓝，每页标题改成结论句&quot;</p>

<p><strong>一个经验：</strong>做 PPT 和做 Word 的提示词逻辑不一样。PPT 要&quot;每页一个结论&quot;，Word 要&quot;结构完整、论证闭环&quot;。别用同一套话要求它们。</p>

### 10-3 技能精选：录音转文字

<p><strong>解决什么：</strong>会议录音、访谈录音、课程录音、语音备忘 → 可编辑文字，最好还能分角色。</p>

<p><strong>三种用法：</strong></p>

<p>①<strong>纯转写</strong>：出一份逐字稿，适合需要原文留证的场景（访谈、口供式记录）。</p>

<p>②<strong>转写 + 整理</strong>：直接出会议纪要（谁说的、定了什么、谁负责），适合内部会议。</p>

<p>③<strong>转写 + 提炼</strong>：出要点清单，适合课程、长访谈——你不需要逐字看，只要干货。</p>

<p><strong>指令模板：</strong>&quot;把这个录音转成文字，然后整理成会议纪要：① 参会人与各自主要观点 ② 达成的决议（只写明确说定的）③ 待办表（事项/责任人/截止时间）④ 待定事项。逐字稿另存一份，不要删改原话。&quot;</p>

<p><strong>四个实操经验：</strong>① 录音质量决定一切——手机放桌上录，比放兜里好十倍；② 说话人超过四个，分离会串，重要会议建议用会议软件的录音；③ 专业术语、人名提前给对照表；④<strong>数字和金额必须复核</strong>，转写最容易错的就是数字。</p>

### 10-4 技能精选：视频下载

<p><strong>解决什么：</strong>把需要的视频/音频存到本地，用于资料留存、二次剪辑、内容分析。</p>

<p><strong>用法：</strong>给它链接，说清要什么（原画质/只要音频/指定时间段），它会下到指定目录。</p>

<p><strong>指令模板：</strong>&quot;把这个链接的视频下载到 [目录]，要 [最高画质/720p]，命名成 [规则]。同时提取音频存成 mp3。&quot;</p>

<p><strong>三条必须说清的边界（这一节很重要）：</strong></p>

<p>①<strong>只下你有权使用的。</strong>自己的内容、明确授权的内容、公开课/公开资料可以；别人的付费课程、有版权的影视内容，下载和二次传播都有法律风险。</p>

<p>②<strong>不要用于商业转载。</strong>下载别人的视频剪一剪发出去，是侵权高发区。</p>

<p>③<strong>平台规则也要看。</strong>有些平台明确禁止下载，工具能做不等于可以随便做。</p>

<p>工具是中性的，用途决定性质。这一条没有商量空间。</p>

### 10-5 技能精选：Web Search（抓实时信息）

<p><strong>解决什么：</strong>模型的知识有截止时间，问它&quot;现在多少钱&quot;&quot;最近出了什么&quot;它可能编。搜索技能让它<strong>先查再答</strong>。</p>

<p><strong>怎么用才对：</strong></p>

<p>①<strong>要求它给出处。</strong>&quot;每个结论后面注明来源链接&quot;——这条能挡掉大部分幻觉。</p>

<p>②<strong>要求它说清信息时间。</strong>&quot;这条信息是哪天发布的&quot;——价格、政策、人事变动，时间点比内容本身还重要。</p>

<p>③<strong>多源交叉。</strong>&quot;至少查三个来源，不一致的地方标出来&quot;。</p>

<p>④<strong>区分事实和推测。</strong>&quot;查到的写&#39;据XX报道&#39;，你推断的写&#39;推测&#39;&quot;。</p>

<p><strong>指令模板：</strong>&quot;查一下 [主题] 的最新情况，要求：① 至少三个独立来源 ② 每条结论注明来源链接和发布时间 ③ 来源之间不一致的地方单独列出 ④ 事实与推测分开标注 ⑤ 最后给我一段 200 字内的总结，可以直接引用。&quot;</p>

<p><strong>什么时候必须用搜索：</strong>任何涉及价格、政策、法律条文、公司信息、人名职务、时事的内容。<strong>不用搜索直接答的，等于让它猜。</strong></p>

### 10-6 技能精选：高级设计感页面总结

<p><strong>解决什么：</strong>把一堆内容（笔记、报告、资料）做成一张好看的、能分享的网页——不是干巴巴的文字堆。</p>

<p><strong>适合的场景：</strong>读书笔记整理、项目复盘可视化、课程笔记分享、给客户的一页式方案、内部知识卡片。</p>

<p><strong>怎么要求才好看（关键是给具体的视觉约束）：</strong></p>

<p><strong>指令模板：</strong>&quot;把 [内容] 做成一个单页 HTML：① 风格：[简约商务/杂志风/科技感]，配色不超过三种（主色 [XX]，辅助 [XX]，背景浅灰白）② 结构：大标题 + 摘要卡片 + 3-5 个内容区块 + 结尾要点 ③ 每个区块用小图标或数字序号开头 ④ 字体：标题粗体，正文常规，行距宽松 ⑤ 手机端要能正常显示（响应式）⑥ 不要用花哨动画，不要渐变滥用。输出单个 html 文件。&quot;</p>

<p><strong>三个让它更好看的技巧：</strong></p>

<p>①<strong>给参考。</strong>贴一个你觉得好看的页面链接或截图，说&quot;照这个风格&quot;——比形容词有效一百倍。</p>

<p>②<strong>限制颜色数。</strong>不限的话它会给你五种主色，一定难看。说死&quot;不超过三色&quot;。</p>

<p>③<strong>要求留白。</strong>&quot;内容区块之间留足空距，宁可少放内容也别挤&quot;。这是业余和专业最明显的分界。</p>

### 10-7 技能精选：Skill 安装安全防护卫士

<p><strong>为什么这一节必须看：</strong>第三方技能本质是<strong>别人写的指令 + 可能包含的脚本</strong>。装之前你不知道它会读什么文件、连什么服务、把数据发到哪。这跟装一个来源不明的软件是同一类风险。</p>

<p><strong>装之前检查五件事：</strong></p>

<table><thead><tr><th><p>检查项</p></th><th><p>具体看什么</p></th></tr></thead><tbody><tr><td><p><strong>① 来源</strong></p></td><td><p>官方市场 / 认识的作者 / 群里转发的压缩包——风险依次递增。来源不明的，宁可不装。</p></td></tr><tr><td><p><strong>② 技能说明文件</strong></p></td><td><p>打开 SKILL.md 通读一遍。它自称能干什么、实际指令里有没有超出这个范围的动作。</p></td></tr><tr><td><p><strong>③ 有没有脚本</strong></p></td><td><p>技能目录里如果有 .py / .sh / .js / .exe，重点看它执行什么命令、往哪发数据。</p></td></tr><tr><td><p><strong>④ 网络请求</strong></p></td><td><p>有没有往陌生域名 POST 数据。有上传行为的，直接放弃。</p></td></tr><tr><td><p><strong>⑤ 权限范围</strong></p></td><td><p>它要读的目录是不是过大（比如整个 C 盘）、要不要账号密码、要不要执行系统命令。</p></td></tr></tbody></table>

<p><strong>五条红线（碰到一条就别装）：</strong></p>

<p>① 要求你把账号密码、API Key 填进技能文件里；<br/>② 有往不明服务器上传文件/数据的代码；<br/>③ 要求关闭安全软件或提权；<br/>④ 脚本里出现删除类命令（rm -rf、del /s、格式化）；⑤ 混淆过的代码（看不懂的乱码式脚本）——正常技能不需要混淆。</p>

<p><strong>安全的使用习惯：</strong></p>

<p>· 新技能先在<strong>测试目录</strong>跑，别直接对着重要文件用；<br/>· 涉及敏感数据（合同、财务、客户名单）的活，不要交给来源不明的技能；<br/>· 装完先让它做一件无关紧要的小事，观察它的行为（读了哪些文件、有没有联网）；· 定期清理不用的技能——装得越多，攻击面越大。</p>

<p><strong>自己封装技能（最安全，也最贴合你的业务）：</strong></p>

<p>把你稳定跑过三次以上的指令，整理成一份技能文档，包含六部分：<strong>角色</strong>（它是谁）、<strong>适用场景</strong>（什么时候用）、<strong>输入要求</strong>（需要给什么）、<strong>执行步骤</strong>（怎么做）、<strong>输出格式</strong>（交什么）、<strong>禁忌</strong>（不能做什么）。</p>

<p>自己写的技能没有第三方风险，而且懂你的业务——这是长期最值钱的资产。</p>

> [!TIP]
> 💡
> <p><strong>第 10 章验收：</strong>装三个技能就够——录音转文字（最通用）、Web Search（最防幻觉）、Office 套件（最出活）。装之前按 10-7 的五项检查过一遍。</p>

## 第 11 章 专家中心

### 11-1 专家就干专业的话

<p><strong>一句话：专家是&quot;带着行业方法论来的角色包&quot;，你不需要会写提示词，直接找对专家就行。</strong></p>

<p><strong>它和普通对话的区别：</strong></p>

<table><thead><tr><th><p>维度</p></th><th><p>普通对话</p></th><th><p>专家</p></th></tr></thead><tbody><tr><td><p>口吻</p></td><td><p>通用助手腔</p></td><td><p>该行业的口径（法务说条款、财务说科目、HR 说制度）</p></td></tr><tr><td><p>方法论</p></td><td><p>你自己给框架</p></td><td><p>自带上岗框架和工作流</p></td></tr><tr><td><p>判断标准</p></td><td><p>通用</p></td><td><p>行业惯例、合规红线、常见坑</p></td></tr><tr><td><p>你要做的</p></td><td><p>说清每一步要求</p></td><td><p>说清你的具体情况，剩下的它来问</p></td></tr></tbody></table>

<p><strong>怎么用（三步）：</strong></p>

<p>① 左侧「专家·技能·连接器」→ 专家中心，按分类找（投资财务、法律合规、市场营销、数据分析、招聘 HR、教育、医疗等）。</p>

<p>② 选中后，<strong>先把背景一次说清</strong>：你是谁、什么行业、要解决什么、已有的材料是什么。专家最怕你只给一句话。</p>

<p>③ 让它先问你几个问题再动手——好的专家会先做需求澄清，这个环节别跳过，它问的问题往往就是你想漏的。</p>

<p><strong>什么活该找专家：</strong>需要专业判断的（合同条款风险、财务口径、绩效方案设计）、需要行业惯例的（投标文件格式、招聘话术）、以及你不熟但要做一次的活（第一次写专利交底书、第一次做尽调清单）。</p>

<p><strong>什么活不用找专家：</strong>纯执行类的（改格式、批量改名、合并表格）——这些普通对话加一个技能就够，找专家是浪费。</p>

### 11-2 专业案例，与整套课程的总结

<p><strong>三个&quot;专家 + 技能&quot;组合的实战思路（照着套）：</strong></p>

<table><thead><tr><th><p>场景</p></th><th><p>组合</p></th><th><p>怎么走</p></th></tr></thead><tbody><tr><td><p><strong>合同初审</strong></p></td><td><p>法律专家 + 文档技能</p></td><td><p>把合同丢给法律专家，要求&quot;逐条标出对我方不利的条款、缺失的必要条款、模糊表述&quot;，出一份风险清单；再用文档技能做成批注版 docx</p></td></tr><tr><td><p><strong>季度经营分析</strong></p></td><td><p>财务/数据分析专家 + 分析技能</p></td><td><p>先让专家定分析框架（看哪几个指标、什么算异常），再让它按框架跑数据、出结论、做 HTML 报告</p></td></tr><tr><td><p><strong>岗位 JD + 面试题</strong></p></td><td><p>招聘专家 + 文档技能</p></td><td><p>说清岗位、团队情况、要解决什么问题，让专家出 JD + 三轮面试题 + 评分表，再用文档技能排版成册</p></td></tr></tbody></table>

<p><strong>整套 11 章，最后浓缩成五句话：</strong></p>

<p><strong>一、它给成品，不给答案。</strong>你派活，不是提问。区别就在于你要说清交付物是什么。</p>

<p><strong>二、说清四件事：身份、任务、要求、交付形式。</strong>说不清这四件，再强的模型也只能猜。</p>

<p><strong>三、批量操作先给方案，再动手。</strong>这条能保住你所有的数据。</p>

<p><strong>四、值得定时的活，一定要定时。</strong>手动用一百次，不如配一次自动跑。</p>

<p><strong>五、别人做好的技能和专家，直接用。</strong>别什么都从零搭——这是普通人缩短差距最快的一步。</p>

<p><strong>接下来怎么走（给你一个具体的下一步）：</strong></p>

<p>不要试图一次学完。今天只做一件事：<strong>找出你上周干过的最烦的那件活，用第 4 章的公式重新派一遍。</strong>跑通了，你就有了第一个属于自己的流程；跑不通，你就知道该回看哪一章。学习这件事，一个跑通的案例胜过十篇教程。</p>
