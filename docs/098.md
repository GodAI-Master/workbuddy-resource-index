本篇是「旅行规划与回忆工作台」的完整搭建 SOP。一句话：把「想去哪、什么时候去、花多少钱」从收藏夹里那一堆链接，变成一张能出发的行程表；回来之后，自动变成一份能翻的回忆。
一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：收藏了 200 个「此生必去」，真到要出发时，发现自己完全没规划，最后报了个跟团。
瞬间二：旅行回来，照片存在手机里，行程忘光了。三年后翻到照片，只能说「这是在某个海边」。
瞬间三：每次旅行都超预算。出发前算 3000，回来花 6000，钱花在哪完全想不起来。
旅行有两个高价值时刻：出发前的规划和回来后的整理。前者决定玩得好不好，后者决定这段回忆能不能留得住。这个工作台两个都管。

为什么是"桌面软件"而不是表格？旅行的钱和记忆都是「一次性」的——不记就没了。你可能记得「那次旅行很好玩」，但记不住「那家面馆叫什么、在哪条街、多少钱一碗」。软件的价值是让这些细节留得下来，下次去还能找到。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\旅行规划。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备几条真实数据（纸面想好就行，不用打字）：你想去的 3 个地方（连大概预算）；最近一次旅行的花费；最近一次旅行的行程（哪怕只有大概）。

唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。
三、第一步：跟 WorkBuddy 把话说清楚（提示词一）
3.1 开工操作
打开 WorkBuddy，点新建任务，模式选 Agent 模式（它能自己动手建文件，别选纯问答模式）。
把工作目录设成第二章建好的那个文件夹（比如 D:\我的工作台\旅行规划）。设错也不致命，就是文件会落别处，你得多翻一下。
在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"旅行规划与回忆工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我每年出去旅行 1-3 次。痛点是：收藏了一堆地方但没规划、每次都超预算、回来照片一堆但行程忘光了。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个旅行规划与回忆工作台"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"一年大概出去几次？"——1-3 次，影响结构
"要管预算吗？"——要，出发前估，回来对
"行程要记多细？"——按天，每天 2-3 件事就够
"要不要多人一起用？"——不要，先做单人视角
"回忆要记什么？"——照片索引、最好吃的一顿、遗憾和下次想去
这里出现第一个"需要你输入"的点：上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）

第一版只验"通不通"，不验"好不好看"。丑、慢、布局怪，都留到第七章的迭代环节统一处理。第一版就追求完美，你会陷入无止境的细节，搭不完。
六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
录进去：你想去的 3 个地方（连预算）、最近一次旅行的真实花费（能想起多少写多少）、那次旅行的行程（按天回忆）。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它要求每个景点填「门票价格」，可你还没查；比如它把「同行人数」设成必填，你一个人去。
第二类：流程不顺手。比如排行程要点「新建旅行」→「新建日」→「新建活动」，三层；你想的是一天一行往下写。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开行程页，看到的是你真实去过或计划去的那次旅行，日期和地点都对。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 旅行工作台备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每次用完固定导出一次，存进 D:\我的工作台\备份。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：
11.1 排行程
自己排容易排成旅游团，一天八个景点。

我要去【城市】玩【X】天，预算【X】元，喜欢【自然风光/人文/美食/不赶路】。请帮我排一个行程：每天 2-3 个点，说明交通方式和大概耗时，并标出哪一天最累（我会留出休息时间）。不要排得像旅游团。
11.2 预算估算
出发前算准，回来才不会心疼。

我要去【城市】玩【X】天，住【青旅/民宿/酒店】，从【出发地】出发。请帮我估算总预算，分成交通、住宿、餐饮、门票、其他五项，给出「省着花/正常/舒服」三档。
11.3 回忆整理
回来第二天就写，晚了就只剩照片。

这次旅行我去了【城市】，行程是【粘贴】，花了【X】元。印象最深的是【……】。请帮我写一段 300 字以内的旅行小结，不要攻略腔、不要「值得一去」，就像跟朋友聊天一样讲这次旅行。
注意分工：本地软件没有 AI（它只存数据、做展示），AI 能力全部走 WorkBuddy 对话完成。这个分工反而是最稳的组合——软件不崩、AI 不用嵌进去，各干各的。
