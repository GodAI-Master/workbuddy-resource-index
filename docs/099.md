# 13 植物养护与家庭园艺工作台 · 完整搭建 SOP

## WorkBuddy 工作台全套资料 · 第 13 篇

<p><strong>本篇是「植物养护与家庭园艺工作台」的完整搭建 SOP。</strong>一句话：把「这盆该浇水了吗、上次施肥什么时候、为什么它叶子黄了」变成每株植物自己的档案，让养死的植物变成经验而不是遗憾。</p>

## 一、这个工作台解决什么问题

### 1.1 先看看你有没有这三个瞬间

<p><strong>瞬间一：</strong>买回来的时候绿油油，三个月后黄叶、掉叶、烂根。你完全不知道是哪一步做错了。</p>

<p><strong>瞬间二：</strong>十几盆花，浇水全靠「看着差不多」，有的浇多了烂根，有的干死了。</p>

<p><strong>瞬间三：</strong>想抢救一盆快死的植物，上网搜「叶子发黄怎么办」，跳出二十种原因，你不知道该信哪个。</p>

<p>养植物最大的错觉是「我浇水了」。真正决定死活的是<strong>节奏和记录</strong>：这盆多久浇一次、上次施肥是哪天、上次换盆什么时候。这些你记不住，但软件能。</p>

### 1.2 成品长什么样：一个桌面上的小软件

<p>先说清楚最终形态，免得你搭到一半发现跟想的不一样：</p>

<p><strong>它会是你电脑桌面上的一个图标，双击就打开一个独立窗口，长得像个软件。</strong>不用联网也能用，所有数据都存在你自己电脑里，不需要注册任何账号，不需要装任何其他东西。</p>

<p>打开之后，它有四个页面，各管一件事：</p>

<table><thead><tr><th><p>页面</p></th><th><p>管什么</p></th><th><p>你什么时候打开它</p></th></tr></thead><tbody><tr><td><p>今天</p></td><td><p>今天该浇水的植物（按各自周期排）</p></td><td><p>每天早上</p></td></tr><tr><td><p>植物档案</p></td><td><p>每株一页：品种、入手日期、光照位置、浇水周期、施肥周期</p></td><td><p>买回来时</p></td></tr><tr><td><p>观察记录</p></td><td><p>每次异常：哪天、什么症状、做了什么处理、后来怎样</p></td><td><p>发现问题时</p></td></tr><tr><td><p>死亡档案</p></td><td><p>养死的植物也留档：死因、教训</p></td><td><p>死了之后</p></td></tr></tbody></table>

### 1.3 明确不做什么（这个比做什么更重要）

<p>第一版<strong>故意</strong>砍掉这些功能，别自己加戏：</p>

<table><thead><tr><th><p>不做的事</p></th><th><p>为什么不做</p></th></tr></thead><tbody><tr><td><p>拍照识别品种</p></td><td><p>需要模型和接口，本地软件做不到</p></td></tr><tr><td><p>网购植物、比价</p></td><td><p>偏离核心</p></td></tr><tr><td><p>社区晒花</p></td><td><p>会变成社交软件</p></td></tr><tr><td><p>智能花盆联动</p></td><td><p>涉及硬件</p></td></tr></tbody></table>

> [!TIP]
> 💡
> <p><strong>为什么是&quot;桌面软件&quot;而不是表格？</strong>植物死的时候，你永远不知道是哪一步错的——因为中间的过程没记。软件的价值是让「上次浇水是 5 天前、上次施肥是 20 天前、上周搬到了阴面」这些信息在出事的时候能翻出来。这一条能救活很多盆。</p>

## 二、开工前的准备（10 分钟，全在你这边）

<p>正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。</p>

### 2.1 准备清单

<ol><li><strong>WorkBuddy 客户端装好、登录。</strong>没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。</li><li><strong>在电脑上建一个空文件夹。</strong>比如<code>D:\我的工作台\植物养护</code>。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。</li><li><strong>挑一个你顺手的浏览器。</strong>Edge 或 Chrome 都行。<strong>定了就一直用它开这个软件</strong>，因为数据跟着浏览器走（原因见第十章）。</li><li><strong>准备几条真实数据</strong>（纸面想好就行，不用打字）：你现在养的植物（名字或大概品类）；每盆大概多久浇一次水；最近死掉的一盆是什么情况。</li></ol>

> [!TIP]
> 💡
> <p><strong>唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。</strong>别用&quot;项目A、测试数据&quot;这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。</p>

### 2.2 全程你会用到的角色分工

<p>整套流程就两个角色，别搞混：</p>

<ul><li><strong>WorkBuddy：施工队。</strong>所有代码、界面、功能都是它写，你一行代码都不用碰。</li><li><strong>你：甲方 + 验收员。</strong>你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。</li></ul>

<p>这个分工意味着：<strong>SOP 里所有&quot;做&quot;的动作都是复制粘贴提示词，所有&quot;判断&quot;的动作是你亲手点一遍。</strong>哪一步跳过了&quot;自己点一遍&quot;，后面必然返工。</p>

## 三、第一步：跟 WorkBuddy 把话说清楚（提示词一）

### 3.1 开工操作

<ol><li>打开 WorkBuddy，点<strong>新建任务</strong>，模式选<strong>Agent 模式</strong>（它能自己动手建文件，别选纯问答模式）。</li><li>把<strong>工作目录</strong>设成第二章建好的那个文件夹（比如<code>D:\我的工作台\植物养护</code>）。设错也不致命，就是文件会落别处，你得多翻一下。</li><li>在输入框粘贴下面这段提示词，回车。</li></ol>

### 3.2 提示词一：需求确认版（先别让它写代码）

```
我要做一个"植物养护与家庭园艺工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。需求背景：我养了十几盆植物。痛点是：总忘浇水和施肥、不同植物周期不一样记不住、叶子黄了不知道原因、养死了不知道错在哪。
```

### 3.3 为什么第一步是&quot;复述&quot;而不是&quot;开做&quot;

<p>你直接说&quot;帮我做个植物养护与家庭园艺工作台&quot;，它会按它想象中的样子给你一个<strong>通用的</strong>东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。</p>

<p>先让它复述，等于把&quot;需求的解释权&quot;拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。</p>

### 3.4 它大概会问你什么（提前有数，答得就快）

<ul><li>&quot;养了多少盆？&quot;——大概数量，影响列表长度</li><li>&quot;要不要分室内室外？&quot;——要，光照条件不一样</li><li>&quot;浇水周期我自己定还是它推荐？&quot;——我先按经验填，它按品种给建议</li><li>&quot;要不要记施肥？&quot;——要，这是最多人忽略的一项</li><li>&quot;养死的要不要记？&quot;——要，这是最有价值的部分</li></ul>

<p><strong>这里出现第一个&quot;需要你输入&quot;的点：</strong>上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。</p>

## 四、第二步：让它先出方案，还是别写代码（提示词二）

### 4.1 提示词二：要一份方案

<p>需求确认完，先别放它写代码。继续粘贴：</p>

```
需求确认了。现在还是不要写代码。请先给我一份搭建方案，包含四部分：
1. 页面结构：这个软件一共几个页面，每个页面放什么内容；
2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一条记录"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。方案用中文写，控制在 500 字以内，不要贴代码。
```

### 4.2 方案怎么验收：只看三样

<p>500 字方案一分钟看完，重点盯三处：</p>

<table><thead><tr><th><p>看什么</p></th><th><p>合格标准</p></th></tr></thead><tbody><tr><td><p>每株有「浇水周期」和「上次浇水日」</p></td><td><p>这两个字段一有，它就能算出今天该浇哪几盆</p></td></tr><tr><td><p>有「光照位置」</p></td><td><p>挪过位置的植物出问题，八成是光照变了</p></td></tr><tr><td><p>有异常记录</p></td><td><p>症状加处理加结果，这才是经验</p></td></tr></tbody></table>

### 4.3 方案不满意怎么改（提示词三，通用句式）

```
方案整体可以，改三处：
1. 今天页只显示今天该浇和逾期未浇的，按逾期天数排序；
2. 植物档案按最近出问题的排前面；
3. 把识别、比价、社区全砍掉。确认后给我更新版方案，还是不要代码。
```

> [!NOTE]
> 📌
> <p><strong>一次最多改三处。</strong>这不是规矩是经验：改的条数越多，每一处改得越潦草，而且你回头都验不了。</p>

## 五、第三步：生成第一版（提示词四，这次真写代码）

### 5.1 提示词四：带四条硬约束

<p>方案点头之后，粘贴这段。四条硬约束一条都别删——每一条背后都是踩过的坑：</p>

```
方案确认，开始做第一版。四条硬要求，必须全部满足：
1. 只做成一个单独的 HTML 文件，所有代码都写在这一个文件里，不要拆多个文件，不要安装任何依赖，做完我双击这个文件就能用；
2. 数据全部存在我电脑本地，刷新页面、关掉浏览器再打开，数据都不能丢；
3. 界面全中文，做得干净、字大、好点，我每天要打开好几次，别做成演示 demo 的样子；
4. 浇水记录要能一次勾选多盆（我经常一次浇好几盆），不要一盆一盆点
做完以后，你自己把整个软件从头到尾完整点一遍，告诉我哪里顺手、哪里会让我困惑。做完告诉我：文件叫什么名字、放在哪个文件夹。
```

### 5.2 四条硬约束分别防什么坑

<table><thead><tr><th><p>约束</p></th><th><p>防的坑</p></th></tr></thead><tbody><tr><td><p>单文件、零依赖</p></td><td><p>不拆文件就没有环境问题，双击就能开</p></td></tr><tr><td><p>数据存本地</p></td><td><p>养了什么植物、放在哪，属于家庭隐私</p></td></tr><tr><td><p>全中文、手机上能用</p></td><td><p>浇水时手上是湿的，只有手机在旁边</p></td></tr><tr><td><p>支持批量勾选</p></td><td><p>十几盆一盆盆点，你第三天就会放弃</p></td></tr></tbody></table>

### 5.3 第一版验收清单（5 分钟点完）

<p>WorkBuddy 做完后，去工作目录找到那个 HTML 文件，<strong>双击打开</strong>，然后逐条打勾：</p>

<ol><li>建 5 盆植物，各有浇水周期</li><li>一次勾选 3 盆已浇水，今天的待浇列表相应减少</li><li>给一盆记一条异常（叶子发黄、已减少浇水）</li><li>关掉重开数据不丢</li><li>界面中文，植物名一眼看得清</li></ol>

> [!TIP]
> 💡
> <p><strong>第一版只验&quot;通不通&quot;，不验&quot;好不好看&quot;。</strong>丑、慢、布局怪，都留到第七章的迭代环节统一处理。第一版就追求完美，你会陷入无止境的细节，搭不完。</p>

## 六、第四步：把真实数据喂进去（决定它是玩具还是工具）

<p>验收通过别急着庆祝。<strong>这一步最容易被跳过，也是决定工作台生死的一步。</strong></p>

### 6.1 操作

<p>录进去：你现在真实养的植物（能想起几盆写几盆）、每盆的浇水周期（凭经验写）、最近死掉那一盆的完整过程（怎么死的、你试过什么）。最后这条最有价值——它就是你以后不再犯的错。</p>

### 6.2 录完你会遇到两类问题——这是好事

<p><strong>第一类：字段不合手。</strong>比如它要求填「盆径」「土壤配比」这种专业字段，你根本不知道；比如它把「施肥周期」设成必填，你从来没施过肥。</p>

<p><strong>第二类：流程不顺手。</strong>比如浇水要点进每盆、点按钮、确认；你想的是列表上全部勾掉。比如今天该浇的列表混在全部植物里，要自己找。</p>

<p>拿张便签或者开个备忘录，标题就写&quot;工作台待改清单&quot;。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。</p>

> [!NOTE]
> 🎯
> <p><strong>本章验收：</strong>打开今天页，看到「这 3 盆该浇水了」，而且确实是你 5 天没浇的那几盆。</p>

## 七、第五步：迭代优化（8 条现成提示词，抄就完了）

<p>迭代不靠灵感，靠&quot;用的时候哪里硌手&quot;。第六章攒的&quot;待改清单&quot;就是原料。以下 8 条覆盖这个工作台最常见的问题，直接抄，方括号里的换成你的情况：</p>

<table><thead><tr><th><p>哪里硌手</p></th><th><p>直接抄的提示词</p></th><th><p>改完怎么验</p></th></tr></thead><tbody><tr><td><p>浇水太麻烦</p></td><td><p>今天页每盆右边一个勾，可以多选后一次性标记「已浇水」</p></td><td><p>勾几下搞定</p></td></tr><tr><td><p>忘了施肥</p></td><td><p>施肥单独一个周期，跟浇水分开算，到期在首页提示</p></td><td><p>能提醒</p></td></tr><tr><td><p>不知道黄叶原因</p></td><td><p>异常记录改成点选症状（黄叶/落叶/烂根/徒长/虫害）加我做过的处理</p></td><td><p>点选就行</p></td></tr><tr><td><p>想不起买多久了</p></td><td><p>每盆显示「入手 X 个月」</p></td><td><p>一眼看到</p></td></tr><tr><td><p>挪过位置忘了</p></td><td><p>加「位置变更」记录，挪动时记一笔</p></td><td><p>能追溯</p></td></tr><tr><td><p>养死了想留教训</p></td><td><p>死亡档案单独一栏，写死因和一句教训</p></td><td><p>有记录</p></td></tr><tr><td><p>想按位置看</p></td><td><p>加「按位置分组」视图：客厅、阳台、卧室</p></td><td><p>能分组</p></td></tr><tr><td><p>想给朋友看</p></td><td><p>加「导出我的植物清单」，生成一段可复制的文字</p></td><td><p>能复制</p></td></tr></tbody></table>

### 7.1 迭代的三条纪律

<ul><li><strong>一次只提 1~3 条。</strong>一次丢十条过去，它改出来的东西你自己都验不过来，坏一处你还不知道是哪条改坏的。</li><li><strong>改完用一遍，再提下一轮。</strong>改动生效后至少真实使用半天，硌手的地方会自己冒出来。</li><li><strong>提示词里带现象，别带结论。</strong>说&quot;我点保存没反应&quot;比说&quot;保存功能坏了，你修一下&quot;效果好——前者是证据，后者是让你俩一起猜。</li></ul>

## 八、第六步：装到桌面（让它看起来像个软件）

<p>现在它还只是个 HTML 文件，打开方式是&quot;找到文件 → 双击 → 浏览器里开一个标签页&quot;。这一章把它变成桌面上真正意义的&quot;软件图标&quot;。</p>

### 8.1 三种方式对比

<table><thead><tr><th><p>方式</p></th><th><p>怎么做</p></th><th><p>适合谁</p></th></tr></thead><tbody><tr><td><p><strong>方式 A：浏览器快捷方式（推荐）</strong></p></td><td><p>用浏览器打开这个 HTML → 浏览器菜单&quot;更多工具 → 创建快捷方式&quot;（Edge 里是&quot;应用 → 将此站点作为应用安装&quot;）→ 勾选&quot;在窗口中打开&quot; → 桌面出现独立图标，双击就是一个没有地址栏的独立窗口</p></td><td><p>所有人。5 分钟搞定，零成本，推荐首选</p></td></tr><tr><td><p><strong>方式 B：发布为在线链接</strong></p></td><td><p>让 WorkBuddy 用&quot;发布为应用&quot;把这个软件发布成一个网址，电脑手机都能打开，数据可以存云端；之后同样创建桌面快捷方式</p></td><td><p>想在手机上也看一眼、或多台电脑之间同步的人</p></td></tr><tr><td><p><strong>方式 C：打包成 exe</strong></p></td><td><p>用打包工具把网页套一层壳变成独立安装包</p></td><td><p>暂时不建议。要装打包环境、体积大、杀毒软件可能误报，折腾半天收益为零</p></td></tr></tbody></table>

<p><strong>推荐方式 A 的理由：</strong>改动即生效（WorkBuddy 每次改完，你重新打开就是新版）、数据在本机、不依赖任何服务。方式 B 等你确定&quot;我要在手机上用&quot;再升级，别一开始就上。</p>

### 8.2 收尾三件小事

## 十、数据备份（5 分钟一劳永逸，必须做）

### 10.1 先知道风险在哪

<p>本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：<strong>清理浏览器缓存、卸载浏览器、重装系统时，数据会没。</strong>所以备份不是可选项。</p>

### 10.2 先补上导出功能（如果你的第一版没有）

```
给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 植物工作台备份_20261110.json；2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
```

### 10.3 备份的三条规矩

<ol><li><strong>每次用完固定导出一次</strong>，存进<code>D:\我的工作台\备份</code>。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。</li><li><strong>换电脑、清缓存、重装系统之前，先导出。</strong>记住：清浏览器缓存 = 清空工作台，没有例外。</li><li><strong>恢复方法：</strong>点&quot;导入数据&quot;，选最新的 JSON 文件，确认。数据原样回来。</li></ol>

## 十一、进阶：让 WorkBuddy 继续替你干活

<p>软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：</p>

### 11.1 黄叶诊断

<p>叶子发黄有二十种原因，但你只符合其中两三种。</p>

```
我这盆【品种】最近出现【叶子从下往上发黄、边缘发干】。养护情况：放在【南阳台】，每【7】天浇一次水，上次施肥是【20】天前，室内温度【22】度。请列出最可能的三个原因，按可能性排序，每个原因告诉我怎么验证、怎么处理。
```

### 11.2 品种养护建议

<p>买之前问清楚，比死了再查有用。</p>

```
我准备养一盆【品种】，放在【北向卧室，光照一般】。请告诉我：浇水周期、光照要求、施肥频率、常见病害，以及新手最容易在哪一步养死它。说人话，别百科腔。
```

### 11.3 死亡复盘

<p>同一盆死两次的人，都是没复盘。</p>

```
我这盆【品种】养了【8】个月死了，过程是【粘贴死亡档案】。请帮我分析死因最可能是什么、我在哪个阶段本可以救回来、下次养同品种要注意什么。
```

<p><strong>注意分工：本地软件没有 AI（它只存数据、做展示），AI 能力全部走 WorkBuddy 对话完成。</strong>这个分工反而是最稳的组合——软件不崩、AI 不用嵌进去，各干各的。</p>
