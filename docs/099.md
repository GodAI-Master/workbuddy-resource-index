本篇是「植物养护与家庭园艺工作台」的完整搭建 SOP。一句话：把「这盆该浇水了吗、上次施肥什么时候、为什么它叶子黄了」变成每株植物自己的档案，让养死的植物变成经验而不是遗憾。
一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：买回来的时候绿油油，三个月后黄叶、掉叶、烂根。你完全不知道是哪一步做错了。
瞬间二：十几盆花，浇水全靠「看着差不多」，有的浇多了烂根，有的干死了。
瞬间三：想抢救一盆快死的植物，上网搜「叶子发黄怎么办」，跳出二十种原因，你不知道该信哪个。
养植物最大的错觉是「我浇水了」。真正决定死活的是节奏和记录：这盆多久浇一次、上次施肥是哪天、上次换盆什么时候。这些你记不住，但软件能。

为什么是"桌面软件"而不是表格？植物死的时候，你永远不知道是哪一步错的——因为中间的过程没记。软件的价值是让「上次浇水是 5 天前、上次施肥是 20 天前、上周搬到了阴面」这些信息在出事的时候能翻出来。这一条能救活很多盆。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\植物养护。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备几条真实数据（纸面想好就行，不用打字）：你现在养的植物（名字或大概品类）；每盆大概多久浇一次水；最近死掉的一盆是什么情况。

唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。
三、第一步：跟 WorkBuddy 把话说清楚（提示词一）
3.1 开工操作
打开 WorkBuddy，点新建任务，模式选 Agent 模式（它能自己动手建文件，别选纯问答模式）。
把工作目录设成第二章建好的那个文件夹（比如 D:\我的工作台\植物养护）。设错也不致命，就是文件会落别处，你得多翻一下。
在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"植物养护与家庭园艺工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我养了十几盆植物。痛点是：总忘浇水和施肥、不同植物周期不一样记不住、叶子黄了不知道原因、养死了不知道错在哪。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个植物养护与家庭园艺工作台"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"养了多少盆？"——大概数量，影响列表长度
"要不要分室内室外？"——要，光照条件不一样
"浇水周期我自己定还是它推荐？"——我先按经验填，它按品种给建议
"要不要记施肥？"——要，这是最多人忽略的一项
"养死的要不要记？"——要，这是最有价值的部分
这里出现第一个"需要你输入"的点：上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）
4.1 提示词二：要一份方案
需求确认完，先别放它写代码。继续粘贴：

1. 页面结构：这个软件一共几个页面，每个页面放什么内容；
2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一条记录"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。
方案用中文写，控制在 500 字以内，不要贴代码。
4.2 方案怎么验收：只看三样
500 字方案一分钟看完，重点盯三处：

这两个字段一有，它就能算出今天该浇哪几盆

挪过位置的植物出问题，八成是光照变了

4.3 方案不满意怎么改（提示词三，通用句式）

1. 今天页只显示今天该浇和逾期未浇的，按逾期天数排序；
2. 植物档案按最近出问题的排前面；

一次最多改三处。这不是规矩是经验：改的条数越多，每一处改得越潦草，而且你回头都验不了。

5.3 第一版验收清单（5 分钟点完）
WorkBuddy 做完后，去工作目录找到那个 HTML 文件，双击打开，然后逐条打勾：

第一版只验"通不通"，不验"好不好看"。丑、慢、布局怪，都留到第七章的迭代环节统一处理。第一版就追求完美，你会陷入无止境的细节，搭不完。
六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
录进去：你现在真实养的植物（能想起几盆写几盆）、每盆的浇水周期（凭经验写）、最近死掉那一盆的完整过程（怎么死的、你试过什么）。最后这条最有价值——它就是你以后不再犯的错。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它要求填「盆径」「土壤配比」这种专业字段，你根本不知道；比如它把「施肥周期」设成必填，你从来没施过肥。
第二类：流程不顺手。比如浇水要点进每盆、点按钮、确认；你想的是列表上全部勾掉。比如今天该浇的列表混在全部植物里，要自己找。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开今天页，看到「这 3 盆该浇水了」，而且确实是你 5 天没浇的那几盆。

7.1 迭代的三条纪律
一次只提 1~3 条。一次丢十条过去，它改出来的东西你自己都验不过来，坏一处你还不知道是哪条改坏的。
改完用一遍，再提下一轮。改动生效后至少真实使用半天，硌手的地方会自己冒出来。
提示词里带现象，别带结论。说"我点保存没反应"比说"保存功能坏了，你修一下"效果好——前者是证据，后者是让你俩一起猜。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 植物工作台备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每次用完固定导出一次，存进 D:\我的工作台\备份。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：
11.1 黄叶诊断
叶子发黄有二十种原因，但你只符合其中两三种。

我这盆【品种】最近出现【叶子从下往上发黄、边缘发干】。养护情况：放在【南阳台】，每【7】天浇一次水，上次施肥是【20】天前，室内温度【22】度。请列出最可能的三个原因，按可能性排序，每个原因告诉我怎么验证、怎么处理。
11.2 品种养护建议
买之前问清楚，比死了再查有用。

我准备养一盆【品种】，放在【北向卧室，光照一般】。请告诉我：浇水周期、光照要求、施肥频率、常见病害，以及新手最容易在哪一步养死它。说人话，别百科腔。
11.3 死亡复盘
