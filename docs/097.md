本篇是「宠物健康与日常养护工作台」的完整搭建 SOP。一句话：把「该驱虫了、该打疫苗了、上次拉肚子是哪天」变成一份随时能翻的健康档案，看病时能直接给医生看。
一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：半夜猫吐了，你慌了，想不起上次这样是什么时候，也不知道要不要去医院，只能上网搜，越搜越怕。
瞬间二：驱虫药买了三盒，放着放着忘了吃。等想起来，已经过了两个月。
瞬间三：带宠物看病，医生问「最近食欲怎么样、大便正常吗、上次疫苗什么时候」，你只能含糊说「还行吧」。
宠物不会说话，所以它所有的健康信息都得靠你记。这个工作台就是替它记病史——这是养宠最容易被忽略、也最救命的一件事。

为什么是"桌面软件"而不是表格？宠物医院最怕的就是「说不清」——主人记不住病程，医生只能靠猜。你手里有一份记了半年的体重、食欲、排便记录，医生的判断会准得多。这份记录，只有你能给它。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\宠物养护。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备几条真实数据（纸面想好就行，不用打字）：宠物的品种、年龄、体重；最近一次疫苗和驱虫的时间；最近一次异常（吐了、拉稀、不吃东西）。

唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。
三、第一步：跟 WorkBuddy 把话说清楚（提示词一）
3.1 开工操作
打开 WorkBuddy，点新建任务，模式选 Agent 模式（它能自己动手建文件，别选纯问答模式）。
把工作目录设成第二章建好的那个文件夹（比如 D:\我的工作台\宠物养护）。设错也不致命，就是文件会落别处，你得多翻一下。
在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"宠物健康与日常养护工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我养了一只猫或狗。痛点是：疫苗驱虫总忘、它不舒服时说不清病程、看病时医生问细节我答不上、体重变化没记录。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个宠物健康与日常养护工作台"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"养的是什么？"——品种、年龄、体重
"要记哪些健康数据？"——体重、食欲、排便、精神，四项够
"疫苗驱虫怎么管？"——按周期提醒，能记上次日期
"要不要记花费？"——要，养宠开销不小
"要不要记异常事件？"——要，这是最关键的
这里出现第一个"需要你输入"的点：上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）
4.1 提示词二：要一份方案
需求确认完，先别放它写代码。继续粘贴：

需求确认了。现在还是不要写代码。请先给我一份搭建方案，包含四部分：
1. 页面结构：这个软件一共几个页面，每个页面放什么内容；
2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一条记录"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。
方案用中文写，控制在 500 字以内，不要贴代码。
4.2 方案怎么验收：只看三样
500 字方案一分钟看完，重点盯三处：

看什么

合格标准

健康记录必须有「日期」和「异常描述」

病程是按天看的，没有日期等于没有记录

疫苗驱虫要有「上次日期」和「周期」

这样它才能自己算下次什么时候

有体重趋势

4.3 方案不满意怎么改（提示词三，通用句式）

方案整体可以，改三处：
1. 首页只显示今天要做的和最近一次异常；
2. 健康记录按时间倒序，最新的在最上面；
3. 把社区、百科、问诊相关的东西全砍掉。
确认后给我更新版方案，还是不要代码。

一次最多改三处。这不是规矩是经验：改的条数越多，每一处改得越潦草，而且你回头都验不了。

5.3 第一版验收清单（5 分钟点完）
WorkBuddy 做完后，去工作目录找到那个 HTML 文件，双击打开，然后逐条打勾：

第一版只验"通不通"，不验"好不好看"。丑、慢、布局怪，都留到第七章的迭代环节统一处理。第一版就追求完美，你会陷入无止境的细节，搭不完。
六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
录进去：宠物真实的疫苗和驱虫时间（想不起就写大概）、最近三次体重、最近一次异常事件（什么时候、什么症状、后来怎么样）。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它要求填「体温」，可你家里没有宠物体温计；比如它把「饮水量」设成必填，你根本测不了。
第二类：流程不顺手。比如记一条健康记录要填五个字段，太累；比如疫苗和驱虫分在两个地方，你要来回找。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开健康档案，能看到宠物最近三次体重和那次异常的记录，你能回忆起当时的情况。

7.1 迭代的三条纪律
一次只提 1~3 条。一次丢十条过去，它改出来的东西你自己都验不过来，坏一处你还不知道是哪条改坏的。
改完用一遍，再提下一轮。改动生效后至少真实使用半天，硌手的地方会自己冒出来。
提示词里带现象，别带结论。说"我点保存没反应"比说"保存功能坏了，你修一下"效果好——前者是证据，后者是让你俩一起猜。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 宠物档案备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每次用完固定导出一次，存进 D:\我的工作台\备份。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：
11.1 症状初判（只作参考，不替代就医）
半夜出事的时候，你最需要的是判断「要不要现在就去医院」。

我的猫或狗今年 X 岁，体重 X 公斤。今天出现【呕吐两次、不吃东西、精神差】，上一次类似情况是【X 天前】。这是我的健康记录（粘贴）。请帮我：
1. 列出几种最可能的原因；
2. 哪些是必须立刻就医的紧急信号；
3. 今晚我可以观察什么来判断要不要去急诊。
注意：你只做参考，最终以兽医诊断为准。
11.2 看病前整理病史
拿着清楚的病史去看病，医生的效率完全不同。

我明天带宠物去医院。这是我的健康记录（粘贴）。请帮我整理成一份病历摘要，包含：基本信息、最近 30 天的异常事件时间线、体重变化、目前的用药，最后列三个我最想问医生的问题。
11.3 喂养方案
喂多了比喂少了更常见，而且更难发现。
