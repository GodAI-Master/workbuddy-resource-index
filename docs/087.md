一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：周五下午四点，领导在群里@你：周报今天发。你翻聊天记录、翻文档、翻脑子，拼凑"这周到底干了啥"，拼了四十分钟，发出去总觉得少了点什么。
瞬间二：手上同时跟着四五个项目，每个项目的关键节点全记在脑子里。某天早上领导问"那个项目周三该交什么来着"，你愣了三秒——完了，忘了。
瞬间三：会上拍板的事，散会就散了。两周后开例会，领导问上次说好的那个事谁在跟，会议室安静得能听见空调声。
这三个瞬间，就是这一个工作台要干掉的。它不解决"你怎么干活"，它解决"你怎么记住、看清、汇报你干的活"。
1.2 成品长什么样：一个桌面上的小软件
先说清楚最终的形态，免得你搭到一半发现跟想的不一样：
它会是你电脑桌面上的一个图标，双击就打开一个独立窗口，长得像个软件。不用联网也能用，所有数据都存在你自己电脑里，不需要注册任何账号，不需要装任何其他东西。
打开之后，它有四个页面，各管一件事：

页面

管什么

你什么时候打开它

今天

今日到期的事、已经逾期的事、本周关键节点

每天早上到工位第一件事

项目

领导问进度、自己心里没底的时候

开完会当场、以及下次会前翻旧账

周报

一键把本周项目进展、完成任务汇总成一段能直接交的周报

每周五下午

为什么是"桌面软件"而不是表格？表格最大的问题是你得"去填"——填的过程就是成本，累的时候你就会放弃。软件把"记"这件事变成顺手点几下，成本够低，才能坚持。这是工作台能不能活过一个月的分水岭。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\职场办公。这是 WorkBuddy 干活的地方，它生成的所有文件都会落在这里，别直接用 C 盘根目录或者桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备三条真实数据（纸面想好就行，不用打字）：你现在手上跟进的 2~3 个真实项目（名字、截止日期、大概进度）；最近开过的一场会（谁参加、拍板了什么事、谁负责）；你上周干的最主要的 5 件事。

唯一需要你动脑的就是第四条，但它是全套 SOP 里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真项目，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。
三、第一步：跟 WorkBuddy 把话说清楚（提示词一）
3.1 开工操作
打开 WorkBuddy，点新建任务，模式选 Agent 模式（它能自己动手建文件，别选纯问答模式）。
把工作目录设成第二章建好的那个文件夹（比如 D:\我的工作台\职场办公）。设错也不致命，就是文件会落别处，你得多翻一下。
在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"职场办公与项目效率工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我是公司职员，同时跟 3-5 个项目，每周要写周报，经常开会。我的痛点是：项目节点容易漏、开会拍板的事没人跟、周五写周报全靠回忆。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个项目管理软件"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"只有你一个人用吗？"——答：是，就我自己。
"项目类型是固定的几种还是随便填？"——答：随便填，不想被预设框死。
"周报要什么格式？"——答：本周完成 / 下周计划 / 需要协调的事，三段。
"数据要不要备份功能？"——答：要，导出成文件存本地。
"要不要提醒功能？"——答：打开软件时能看到逾期和今天到期的就行。
这里出现第一个"需要你输入"的点：上面五个答案是我的版本，你照抄能跑通，但你最好按自己的真实情况改——比如你们周报格式是固定的，就把真实格式告诉它。这五句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）
4.1 提示词二：要一份方案
需求确认完，先别放它写代码。继续粘贴：

需求确认了。现在还是不要写代码。请先给我一份搭建方案，包含四部分：
1. 页面结构：这个软件一共几个页面，每个页面放什么内容；
2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一个项目"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。
方案用中文写，控制在 500 字以内，不要贴代码。
4.2 方案怎么验收：只看三样
500 字方案一分钟看完，重点盯三处：

看什么

合格标准

四个页面在不在

今天 / 项目 / 会议 / 周报，一页都不能少。少一个，你用几天就会发现要的东西没地方放

关键字段够不够

项目必须有"截止日期"和"进度"；任务必须有"负责人"和"到期时间"；会议的行动项必须挂"负责人"和"截止时间"

它砍掉的功能你认不认

它主动砍掉的，你扫一眼，砍得对就不吭声，砍错了就捞回来
4.3 方案不满意怎么改（提示词三，通用句式）

方案整体可以，改三处：
1. 项目列表按截止日期排，快到期的排最前面；
2. 会议里的行动项要能一键转成待办任务；
3. 把 XX 功能砍掉，改成 XX。
确认后给我更新版方案，还是不要代码。

一次最多改三处。这不是规矩是经验：改的条数越多，每一处改得越潦草，而且你回头都验不了。方案阶段改三处以内，能保证每处你都亲自验收过。
五、第三步：生成第一版（提示词四，这次真写代码）
5.1 提示词四：带四条硬约束
方案点头之后，粘贴这段。四条硬约束一条都别删——每一条背后都是踩过的坑：

方案确认，开始做第一版。四条硬要求，必须全部满足：
1. 只做成一个单独的 HTML 文件，所有代码都写在这一个文件里，不要拆多个文件，不要安装任何依赖，做完我双击这个文件就能用；
2. 数据全部存在我电脑本地，刷新页面、关掉浏览器再打开，数据都不能丢；
3. 界面全中文，做得干净、字大、好点，我每天要打开好几次，别做成演示 demo 的样子；
4. 做完以后，你自己把整个软件从打开到写完一份周报完整点一遍，告诉我哪里顺手、哪里会让我困惑。
做完告诉我：文件叫什么名字、放在哪个文件夹。
5.2 四条硬约束分别防什么坑

约束

防的坑

单文件、零依赖

不拆文件就没有环境问题，双击就能开；换个电脑整个文件拷过去照样能用；想发给别人也只是一个文件的事

数据存本地

数据丢失是这类工具的第一死因。刷新就清空的东西没人会用第二次

全中文、不做 demo 样

每天开好几次的东西，界面丑、字小、满屏英文，三天就把你的耐心耗光

让它自己先点一遍

省掉至少一半的返工。它自己走一遍流程发现的低级问题，比你上手之后一条条提快得多

WorkBuddy 做完后，去工作目录找到那个 HTML 文件，双击打开，然后逐条打勾：

第一版只验"通不通"，不验"好不好看"。丑、慢、布局怪，都留到第七章的迭代环节统一处理。第一版就追求完美，你会陷入无止境的细节，搭不完。
六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
把第二章纸面准备的三条真实数据，亲手录进去：2~3 个真实项目（含真实截止日期）、一场真实会议（含真实的行动项）、上周干过的 5 件事。慢没关系，15 分钟足够。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它默认"优先级"分高中低，但你心里想的是"甲方催得紧不紧"；比如它要你填"项目编号"，可你们公司根本没有编号。→ 记下来，这是第七章要改的。
第二类：流程不顺手。比如新建一个项目要点五下、比如"今天"页信息太挤看不过来。→ 也记下来，同样进第七章。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开软件第一屏，看到的是你真实的名字、真实的项目、真实的截止日期——哪怕丑一点，你已经拥有一个"能用的工作台"了。反过来，界面再漂亮，里面全是测试数据，它也只是个 demo。

7.1 迭代的三条纪律
一次只提 1~3 条。一次丢十条过去，它改出来的东西你自己都验不过来，坏一处你还不知道是哪条改坏的。
改完用一遍，再提下一轮。改动生效后至少真实使用半天，硌手的地方会自己冒出来。
提示词里带现象，别带结论。说"我点周报按钮没反应"比说"周报功能坏了，你修一下"效果好——前者是证据，后者是让你俩一起猜。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 项目工作台备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每周五发完周报，顺手导出一次，存进 D:\我的工作台\备份。绑定在"发周报"这个动作后面，就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合干活。三个进阶玩法：
11.1 会议纪要直接变行动项
开会时开录音转写（或拿到会议纪要），直接扔给 WorkBuddy：

这是本周项目会的录音转写。请整理成两部分：
1. 决议列表，编号列出所有拍板事项；
2. 行动项表格：事项 / 负责人 / 截止时间。
整理完告诉我：这些数据我手动录入工作台，还是帮我生成一份可以直接导入的 JSON？如果要生成 JSON，我现在把我工作台导出的数据结构发给你。
开完会两分钟，会里的活就全进工作台了，不用手敲。
11.2 让它看数据、挑毛病
把导出的 JSON 发给 WorkBuddy：

这是我项目工作台导出的全部数据。请分析：
1. 哪些任务逾期超过 3 天还没有进展；
2. 哪个项目风险最大，理由是什么；
3. 给我三条下周优先处理的建议。
用平实的中文说，别客套。
它给出的回答，值得你每周五花 5 分钟认真看一遍——相当于请了个免费的项目顾问。
11.3 周报直接代写
每周五把导出 JSON 发给 WorkBuddy，附一句：

这是我工作台导出的本周数据。按"本周完成 / 下周计划 / 风险与协调事项"三段生成周报，语气自然、像人写的话，每段不超过 5 条。生成后我来改两句话就发。
注意分工：本地软件没有 AI（它只存数据、做展示），AI 能力全部走 WorkBuddy 对话完成。这个分工反而是最稳的组合——软件不崩、AI 不用嵌进去，各干各的。
十二、常见问题快答

问题

答案

数据会上传到云上吗？

本地版不会，数据就在你电脑的浏览器里，断网照常用

换个浏览器打开，数据还在吗？

不在。数据跟浏览器走，固定用一个浏览器开（第八章的规矩）

能多人一起用吗？

本地版不能。要协作就走方式 B（发布在线 + 云数据库），那是另一篇进阶文档的事

做出来的东西太简陋？

不是软件的问题，是提示词的问题。回第七章，一条条提

断电、关机丢数据吗？

不丢，数据在硬盘上。丢数据的只有"清浏览器缓存"，所以第十章的备份要做

能给软件加 AI 功能吗？

纯本地文件里没有 AI。AI 走 WorkBuddy 对话（第十一章），两边配合，反而最稳

我想改字段、加页面？

直接提，参考第七章的句式。记住一次别超过 3 条

打开白屏 / 按钮没反应？

想做成手机 App？

先把电脑版用满两周。真有需求再走方式 B，先别急

□ 至少导出过 1 次备份 JSON
□ 连续使用 5 个工作日以上
13.2 为什么这一篇是全套的总纲
最后说透这套 SOP 的真正价值：它不是教你搭这一个软件，而是教你一套可复制 24 次的方法。
回头看整个流程，其实就五步：说清需求（先复述）→ 先出方案再写码 → 带硬约束生成 → 喂真实数据 → 硌手了再迭代。这套节奏对任何"工作台"都成立——下一回你想搭"健身减脂工作台"，把第 3~7 章提示词里的"职场办公与项目效率"换成"健身减脂"，痛点背景换成你的真实情况，走一遍流程就行。
24 个工作台，区别只在"数据结构"和"你要喂的真实内容"，方法一模一样。这也是为什么全套资料第一篇必须先做它——先会走，再想跑。
