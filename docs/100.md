一、这个工作台解决什么问题
1.1 先看看你有没有这三个瞬间
瞬间一：衣柜塞满，每天早上站着发呆十分钟，最后还是穿那三件。
瞬间二：去年买的衣服标签还没剪，压在柜底。扔了心疼，留着占地方。
瞬间三：出门在外想不起家里有没有那件白衬衫，怕买重复。结果买回来发现有两件。
衣橱的问题不是「衣服少」，是不知道自己有什么、什么在穿。这个工作台干一件很朴素的事：给每件衣服建个档，让你看清自己的真实衣橱。

为什么是"桌面软件"而不是表格？人对自己衣橱的记忆是失真的——你以为自己有 5 件外套，实际有 9 件；你以为那件毛衣常穿，实际去年一次没上身。软件的价值是让数字说话：穿着次数一列出来，你立刻知道该扔什么、该买什么。
二、开工前的准备（10 分钟，全在你这边）
正式开始前，把下面四样备齐。前三样是死要求，第四样需要你动点脑子。
2.1 准备清单
WorkBuddy 客户端装好、登录。没装的到官网下载，桌面端或网页版都行，本教程以桌面端为准。
在电脑上建一个空文件夹。比如 D:\我的工作台\衣橱穿搭。这是 WorkBuddy 干活的地方，它生成的文件都会落在这里，别用 C 盘根目录或桌面，乱。
挑一个你顺手的浏览器。Edge 或 Chrome 都行。定了就一直用它开这个软件，因为数据跟着浏览器走（原因见第十章）。
准备几条真实数据（纸面想好就行，不用打字）：你衣柜里的主要品类（外套、上衣、裤子、鞋）；最常穿的三件；买了但基本没穿的三件。

唯一需要你动脑的就是第四条，但它是全套流程里最不能省的一步。别用"项目A、测试数据"这种假东西——第一天就往里塞真内容，它才会真的帮你记事。用假数据搭出来的软件，归宿都是三天弃坑。
2.2 全程你会用到的角色分工
整套流程就两个角色，别搞混：
WorkBuddy：施工队。所有代码、界面、功能都是它写，你一行代码都不用碰。
你：甲方 + 验收员。你负责说清楚要什么、检查它做出来的东西顺不顺手、决定下一步改什么。
这个分工意味着：SOP 里所有"做"的动作都是复制粘贴提示词，所有"判断"的动作是你亲手点一遍。哪一步跳过了"自己点一遍"，后面必然返工。

在输入框粘贴下面这段提示词，回车。
3.2 提示词一：需求确认版（先别让它写代码）

我要做一个"衣橱穿搭与服装管理工作台"，一个本地网页小软件，做完我会放在桌面双击打开用。在动手之前，你先不要写代码，只做两件事：
1. 用你自己的话复述一遍你理解的需求，列出来给我确认；
2. 针对我没说清楚的地方，一次性问我 5 个以内的问题，我答完你再往下走。
需求背景：我衣服不少，但每天早上还是觉得没得穿。痛点是：不知道自己有什么、买重复过、有些衣服买了没穿过、换季整理特别痛苦。
3.3 为什么第一步是"复述"而不是"开做"
你直接说"帮我做个衣橱穿搭与服装管理工作台"，它会按它想象中的样子给你一个通用的东西——很多功能你用不上，你真正要的它又没做，返工都是从这里开始的。
先让它复述，等于把"需求的解释权"拿回自己手里。它复述歪了，你当场纠正，成本是一句话；做完才发现歪了，成本是重来一遍。
3.4 它大概会问你什么（提前有数，答得就快）
"要记多细？"——按类型加颜色，不记品牌和尺码
"要不要记价格？"——要，能算出每次穿着成本
"穿搭要不要配图？"——要，一张图胜过描述
"季节怎么分？"——春/夏/秋/冬/四季
"要不要管鞋包？"——要，跟鞋一起算搭配
这里出现第一个"需要你输入"的点：上面这几个答案是我给的参考版本，你照抄能跑通，但最好按自己的真实情况改。这几句话，就是你这个工作台和别人的不一样的地方。
四、第二步：让它先出方案，还是别写代码（提示词二）
4.1 提示词二：要一份方案

2. 数据结构：需要存哪些数据，每条数据有哪些字段；
3. 核心操作路径：我日常用它的 3 条主要流程（比如"新建一条记录"从哪点到哪）；
4. 你建议砍掉的功能：哪些听起来有用但第一版不该做。

六、第四步：把真实数据喂进去（决定它是玩具还是工具）
验收通过别急着庆祝。这一步最容易被跳过，也是决定工作台生死的一步。
6.1 操作
录进去：你衣柜里最容易想起来的 10 件（类型、颜色、季节）、最常穿的 3 套搭配、买了但没穿的 3 件（连当时为什么买一起写）。最后这条很扎心，但它能防止你下次再买同样的东西。
6.2 录完你会遇到两类问题——这是好事
第一类：字段不合手。比如它要求填「品牌」和「购买渠道」，你不在乎；比如它的季节只有春夏秋冬，但你有几件是四季都能穿的。
第二类：流程不顺手。比如加一件衣服要填六个字段，加十件就想放弃；比如穿搭组合要一件件从列表里挑，很慢。
拿张便签或者开个备忘录，标题就写"工作台待改清单"。这个清单会持续好几天，你每次用它觉得硌手就添一条，攒够了再让 WorkBuddy 一次改。

本章验收：打开单品库，看到你真实的那十件衣服，而且你能一眼看出哪件「穿着次数是 0」。

十、数据备份（5 分钟一劳永逸，必须做）
10.1 先知道风险在哪
本地版的数据存在你电脑的浏览器里（技术上叫 localStorage）。正常开关机、断网都不会丢。真正的风险只有一个：清理浏览器缓存、卸载浏览器、重装系统时，数据会没。所以备份不是可选项。
10.2 先补上导出功能（如果你的第一版没有）

给软件加两个功能：
1. 右上角一个"导出数据"按钮，把全部数据下载成一个 JSON 文件，文件名自动带当天日期，比如 衣橱工作台备份_20261110.json；
2. 一个"导入数据"按钮，选择 JSON 文件后完整恢复，导入前弹窗让我确认，防止覆盖错。
10.3 备份的三条规矩
每次用完固定导出一次，存进 D:\我的工作台\备份。绑定在一个固定动作后面（比如周日晚上整理完），就不容易忘。
换电脑、清缓存、重装系统之前，先导出。记住：清浏览器缓存 = 清空工作台，没有例外。
恢复方法：点"导入数据"，选最新的 JSON 文件，确认。数据原样回来。
十一、进阶：让 WorkBuddy 继续替你干活
软件搭好只是起点，真正的杠杆是让 WorkBuddy 跟这个工作台配合。三个进阶玩法：
11.1 衣橱诊断
你以为的风格，和数据的统计往往不是一回事。

这是我的衣橱清单（粘贴）：每件的类型、颜色、季节、穿着次数、入手价。请帮我分析：
1. 我实际最常穿的是哪几类（我的真实风格）；
2. 哪些是纯闲置，占总价值多少；
3. 如果我要精简到 40 件，该留哪些、扔哪些。
11.2 搭配建议
不是没衣服，是没想过怎么配。

这是我的单品清单（粘贴）。请帮我配 10 套日常穿搭，要求：每套用现有的单品、适合【上班/周末】、不要重复用同一件外套。每套写清哪几件、什么场合穿。
11.3 补货建议
买之前先问，能省一半钱。

这是我的衣橱清单和穿着频率（粘贴）。请告诉我：我最缺哪一类单品（因为现有的一直在重复穿）、哪一类完全不用再买、如果预算 1000 块，最该添哪两件。
注意分工：本地软件没有 AI（它只存数据、做展示），AI 能力全部走 WorkBuddy 对话完成。这个分工反而是最稳的组合——软件不崩、AI 不用嵌进去，各干各的。
